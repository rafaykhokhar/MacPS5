A stop/unload call yields to the lifecycle manager, validates the supported zero-flags/null-options subset and result storage, and releases only a module dynamically loaded by that caller. Static dependencies and other consumers cannot be bypassed. The caller's dependency pin remains during stop/finalizer execution; only success removes the image, handle and ARM64 translations. These are statically referenced prerequisites, not evidence that startup has executed them. Rust `Heap::malloc` now shares the bounded, aligned, owned allocation/free path with calloc and is exported through the retained native service adapter as libc thunk 9. Native tests cover writing/freeing malloc storage and oversized-allocation failure. Loader/unloader and sysmodule integration still block actual startup.

`start_native_with_files` now drives nested loader requests to completion using an explicit host-supplied address plan and a total request budget. It compiles/starts each requested child, handles missing-file returns and resumes parents in dependency order. Native tests execute a root → middle → leaf loading chain through kernel imports, verify both returned child handles and status writes, enforce dependency stop order and retain unfinished images when the request budget runs out. Nonempty start arguments are now supported as described above; load addresses are supplied by the host, and the real homebrew runner is not yet using this driver.

The Rust executor now atomically publishes `sceKernelLoadStartModule` and its NID through `register_loader_module`. The native guest-driven load fixture uses a real undefined kernel symbol and relocated indirect call, rather than a fixed thunk address in its instructions. `dispatch_native_load` returns guest ENOENT (`0x80020002`, matching the local AnyPS5 kernel error definitions) for valid paths absent from the explicit catalog, without loading anything or writing a successful start status. Tests verify the returned error, unchanged module budget, one-shot continuation and ordinary success path. Invalid arguments, unsupported execution and host/compiler failures still stop explicitly; full kernel error mapping and the older whole-homebrew dispatcher integration remain unfinished.

Latest module-loader integration: `begin_native_load` services a suspended guest request with zero-length start arguments. It validates guest inputs, reads the catalog file, loads/links the image, pins it to the caller, compiles lifecycle and exported-function roots, and starts it. `finish_native_load` checks the child reached Started, writes the optional 32-bit status and resumes the caller with its real module handle. Missing files leave the module budget unchanged; compilation failures retain faulted images and cannot finish successfully. Native ARM64 tests verify the complete guest-request/file/compiler/start/return path, duplicate-load rejection, dependency stop protection, failure retention and teardown. Full guest error-code translation, automatic address selection and publication in the whole-homebrew kernel resolver remain unfinished. The existing whole-homebrew startup still stops at its missing loader API.

Rust is the active implementation language for new work. The CPU translation path now performs ELF code extraction, x86 decoding, reachable control-flow discovery, ARM64 assembly emission, fixture generation and native test orchestration in Rust. It invokes Apple's assembler/compiler to build ARM64 executables. It does not invoke Python or fall back to the old translator.

Arithmetic flag calculation now executes in Rust too. Generated ADD/SUB/CMP/INC/logical/NEG/SBB code calls the integer-only `native_ps5_arithmetic_flags_v1` ABI, returning flags and an explicit validation fault. The helper has no host/guest pointers. `libnative_ps5.a` is emitted alongside the executable and must be linked with generated code; the native runner handles that automatically. Unsafe Rust is denied by default, with narrow allowances for named C ABI exports and the documented memory-callback bridge.

The existing C++ guest memory, remaining CPU helpers, ELF mapping adapter, syscall services and dispatcher remain linked during migration. The existing Objective-C++/C++ Metal and RDNA backend also remains to be migrated. Generated `.hpp` files are temporary ABI registration glue for that runtime. GPU shaders use Metal Shading Language. This is an incremental migration, not an entirely Rust emulator yet.

The selected payload's credential and module-container records are now constructed in Rust (`payload.rs`) and passed by value through `payload_abi.h`. The native runner enables this narrow bridge with `NATIVE_PS5_RUST_PAYLOAD=1`; historical C++ harnesses retain their old fixture when the macro is absent. Credentials cover exactly the observed bytes through `0x8a`, including the 8-byte attribute field at `0x83`. The module container covers its list head and the observed fields at `0xf0`/`0xf8`. The fixture starts attributes at synthetic `0x100` so the guest can preserve that bit while setting `0x80`. This is explicit test state, not a claim about retail credential values or guest authorization semantics. Guest accesses still use guarded, nonidentity kernel mappings.

`strings.rs` implements `strcpy`, `strcat`, `strcmp`, `strncmp` and `strlen` in Rust. The module owns their names and computes their NIDs; the real guest resolver independently finds all five exports. Guest memory callbacks use the retained runtime's guarded reads and whole-range writes. Copies snapshot the source before any write, comparisons use unsigned bytes, zero-count `strncmp` does not read memory, and scans have an explicit 65,536-byte work limit. Invalid memory stops execution with a guest fault rather than pretending success. Length/comparison calls allocate no string buffer. `string_abi.h` and `legacy_abi.cpp` contain only temporary foreign-interface transport; the service semantics and the new native test driver are Rust.

`format.rs` now supplies `sprintf` and replaces the C++ implementation behind `snprintf`/`vsnprintf` on the Rust-enabled path. It supports integer, byte-string, character and pointer conversions; flags, numeric or `*` width/precision; and `hh/h/l/ll/j/z/t` integer lengths. Arguments use the guest SysV general-purpose registers and guarded stack loads. `vsnprintf` copies the 24-byte guest cursor and leaves caller storage unchanged. Output is rendered before one checked write; bounded calls return the full length, truncate to capacity minus one, and permit capacity zero without a destination access. Output is capped at 65,536 characters. Floating-point, wide/locale formatting, positional arguments and `%n` remain unsupported. The bounded entry points preserve the existing guest errno/error-return convention; unsupported `sprintf` conversions stop at an explicit guest fault.

`heap.rs` owns per-runtime `calloc`/`free` allocations in Rust. Backing is zeroed and aligned to 16 bytes; multiplication and rounding are checked. Current limits are 16 MiB per allocation, 256 MiB total and 4,096 live allocations, separate from the retained mmap allocator. Zero-size allocations return a unique live minimum-sized allocation; `free(NULL)` succeeds. Exhaustion returns NULL with guest errno 12. Interior, foreign and double frees stop at an explicit guest fault. Mappings are writable and non-executable, removed before backing is released, and cleaned up with the runtime. This is a bounded initial heap, not a full libc allocator.

`environment.rs` implements bounded `getenv` over a guest pointer table, returning a pointer into the matching guest value. It handles exact names, first-match duplicates, empty values and raw bytes; malformed memory faults explicitly. Scanning is limited to 4,096 entries, 65,536 bytes per string and 1 MiB total. The current runtime supplies an explicitly empty guest environment, independently of the host environment. Populated tables are covered by Rust tests; launch-time environment configuration remains to be connected. Rust also generates the kernel `sceKernelDlsym` export NID so the existing service is visible to the guest resolver.

`loader.rs` now owns a checked ELF64 image loader in Rust, with separately owned guest segments, zeroed BSS, guest load bias, dependency names, retained unresolved imports and transactional RELA relocation (RELATIVE, 64, GLOB_DAT and JUMP_SLOT). Malformed or overlapping relocation writes leave the image unchanged. The native startup runner now enables `NATIVE_PS5_RUST_LOADER=1`: standard and SCE ELF relocation planning executes in Rust through `loader_ffi.rs`, while the retained C++ adapter reserves memory and applies the validated patch list. The adapter stages metadata and validates every destination before committing writes. Resolver failures discard the Rust image and leave mapped bytes unchanged. The independent comparison still compiles the original C++ relocation implementation without this flag. Module service dispatch is not yet connected. SCE table offsets are bounded inside `PT_SCE_DYNLIBDATA`; standard pointers remain guest virtual addresses. Mixed table families work, while conflicting tag aliases, truncated tables and out-of-range symbol indices fail before writes. `imports.rs` preserves module IDs, library tokens, dependency aliases and exact-match precedence through the version-3 loader ABI. TLS, IFUNC and kernel integration with the module lifecycle remain work.

`registry.rs` owns native exports by module in Rust. Registration adds both a plain name and its computed NID, checks conflicts, and commits multi-export batches atomically. Qualified imports cannot escape their owner; unqualified symbols exported by multiple modules are ambiguous even when addresses match. Module removal deletes all owned aliases, with caller-controlled guest quiescence/dependency detachment required before removal. The retained `ImportRegistry` facade uses this Rust implementation when the Rust loader is enabled. Filesystem-backed module discovery and kernel service dispatch remain unimplemented.

`modules.rs` owns loaded Rust images, monotonically allocated handles, image budgets and dependency pins. Loads publish only after relocations resolve, required modules exist, guest address ranges do not overlap and export/entry descriptors validate. It tracks both declared dependencies and actual import providers. Start requires started dependencies; stop/unload reject dependent modules that would retain active calls or pointers. Nonzero status, execution faults, exhausted fuel and executor panics leave the image faulted and pinned until process teardown. `load_dynamic` now discovers exports from the image; the existing explicit-export path remains available for controlled fixtures. Status-returning module start/stop offsets are still explicit descriptors. Automatic dependency discovery, general guest-memory execution and `sceKernelLoadStartModule` integration remain unfinished.

`exports.rs` discovers defined global/weak function and data symbols from bounded dynamic tables. SCE symbol sizes, SysV hash counts and validated dynamic-symbol sections supply table bounds. Local, hidden and undefined entries are excluded; names, extents and executable function permissions are checked before publication. TLS/IFUNC/special sections and GNU-hash-only images without a section-table bound remain unsupported and fail explicitly. The real homebrew exposes 67 eligible exports, including 65 functions, under these rules.

`ownership.rs` resolves qualified export names against producer-local `DT_SCE_MODULE_INFO` and repeated `DT_SCE_EXPORT_LIB` records. It preserves the original qualified name, symbol, local IDs, module major/minor version and library name/version. Unknown IDs, malformed tokens, invalid strings and duplicate IDs fail explicitly; ownership metadata validates before relocation writes commit. Record layouts were checked against [shadPS4's module declarations](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/module.h) and [ELF constants](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/loader/elf.h). This establishes metadata discovery, not PS5 binary compatibility. The Rust module manager now publishes qualified exports under their owning module, library name/version and module major/minor version. Consumer `DT_SCE_IMPORT_LIB` records resolve local IDs to those names and versions; matching requires exact versions, without assuming version compatibility. Qualified tokens are not hashed again or exposed as global aliases. Tests link a producer and consumer whose local IDs differ, reject library/version mismatches, verify transactional registration and keep providers pinned until consumers unload.

The native version-3 loader ABI now transports resolved library names, library versions and packed module major/minor versions in callbacks and pending imports. The C++ mapping adapter copies this metadata into its owned import records, and the version-2 Rust registry resolver validates it before lookup. The explicit absent sentinel is 65536; version zero remains valid. Partial metadata and out-of-range values fail closed. Rust tests exercise scoped relocation through these C ABI functions and retained missing-import records; native startup regression checks compile and run the updated C++ adapter. Older fixtures without import-library records retain their existing module-only behavior. The prototype ABI changed, so native clients must rebuild against the updated headers. Guest module mapping/publication and kernel module-load dispatch still need integration.

`shift_flags.rs` implements the supported 32/64-bit SHL, SHR, SAR, ROL and ROR status flags through an integer-only Rust ABI. Generated ARM64 now calls it directly; the C++ helper remains a reference. Counts are masked to operand width, zero counts preserve flags, and undefined AF/multi-bit OF retain their incoming values. Rust reference tests step one bit at a time across all byte counts and boundary values. The native suite checks the generated instruction results and flags, and a module fixture executes shifts/rotations using the Rust dispatcher and memory path. Eight- and sixteen-bit shift lowering remains unsupported.

`condition.rs` now evaluates all 16 x86 condition predicates for generated branches, CMOV and SETcc through the Rust `native_ps5_condition_v1` ABI. Truth-table tests cover every combination of CF/PF/ZF/SF/OF, ignored flag bits and invalid conditions. The full native instruction regression suite exercises this helper in generated ARM64 code. The initial Rust module executor also accepts resumable regions with external branch edges; native fixtures exercise zero/nonzero paths, a 1,000-iteration loop and fuel termination.

`guest_memory.rs` and `module_executor.rs` now provide an initial Rust-owned module execution path. Borrowed ELF segments and a separate guest stack use checked nonidentity mappings; scalar reads/writes stay within one region, and executable or read-only storage cannot be written. Registered ARM64 blocks are checked against the loaded guest bytes before execution. Rust handles nested guest CALL/RET, matching outer returns, instruction fuel and transition limits. `translate_rust_memory` selects the Rust scalar-memory ABI and explicitly rejects instructions needing unmigrated helpers. Native tests execute stack operations, module data writes, nested calls, permission/range faults, byte mismatches and exhausted budgets. Kernel services and general game execution are not connected to this executor yet. The whole-homebrew startup runner still uses the retained C++ dispatcher/memory; the new path is exercised by the module test.

The Rust module memory path now also handles VEX128/256 vector loads, stores and memory-source XOR. Vector loads/XOR stage a complete result before updating a register, clear the upper YMM half for 128-bit results and support source/destination aliasing. Stores validate the entire range before writing. Invalid widths/registers/alignment, permission violations and crossing accesses fault without partial outputs. The native module fixture exercises unaligned loads, XOR and stores at both widths, upper-half clearing and failed-access preservation. The main startup path still uses its retained C++ memory helpers; the Rust executor routes these operations to distinct Rust ABI names so context layouts cannot be mixed.

The Rust executor now dispatches explicitly registered guest thunks for `strcpy`, `strcat`, `strcmp`, `strncmp` and `strlen` directly to the existing Rust implementations. Its memory map implements their checked memory interface. Calls reserve a real guest return slot, validate the registered continuation, charge service fuel and check the saved return address after completion. Service thunks cannot overlap mapped guest storage. Native ARM64 tests verify all five results, writes, invalid output ranges, unknown services, fuel failures and return-slot corruption. This does not yet wire `sceKernelLoadStartModule`, allocation/environment/formatting services, or process-wide module imports into this executor.

`NativeExecutor::register_string_module` now publishes the five implemented string thunks and their module-owned name/NID exports together. Address conflicts, overflow, invalid module names or registry failure leave both sides unchanged. A native ELF fixture declares an undefined `strcpy`, a dependency and a real RELA call-slot relocation; the Rust loader resolves it against the registered provider, and translated ARM64 calls through that patched slot. Its returned pointer and copied bytes are checked before stop/unload. Missing providers leave no loaded image. This connects import binding to service execution for the tested libc subset; it does not implement missing PS5 kernel APIs or load firmware libraries.

`NativeExecutor::run` and `resume` now support an explicit loader-service suspension. A registered `LoadStartModule` thunk yields its six SysV arguments and an owned continuation containing CPU state, stack and remaining transition budget, with no borrowed memory or raw memory pointer retained. Another guest execution uses a separate stack; resuming supplies the service result without replenishing fuel or transitions. Native ARM64 tests verify suspension, nested execution, result propagation and budget exhaustion. The runtime must still orchestrate request argument reads, file loading, module lifecycle, output writes and dependency retention. The existing synchronous `Executor` interface rejects these requests, and no kernel export is published automatically; real homebrew startup remains blocked at the missing loader API.

Suspended continuations now provide scoped `with_memory` access to their preserved stack and supplied caller/dependency images. This permits service argument reads and result writes without retaining raw mappings. `LoadRequest::read` supports only zero flags/null options, reads a bounded UTF-8 catalog path, checks the complete argument buffer and validates the optional four-byte output before any loading side effects. It rejects malformed paths, unsupported options and inaccessible outputs. Native tests read a stack-backed path, write an image-backed result, reject code/cross-boundary writes and verify preservation across nested execution. Module loading and lifecycle orchestration now support zero-length start arguments, as described above. Executors retain only a stack-size configuration and allocate owned stacks per execution.

`Modules::start_native` now drives constructors and the explicit start routine through the resumable executor. The manager owns pending continuations, exposes checked service memory access and accepts one `resume_native` result per yielded request. Pending and failed initialization remain `Faulted` for lifecycle protection until the entire sequence succeeds, retaining existing dependency pins. Duplicate starts/resumes and pending unloads reject; abandoning a request releases its stack but leaves its partially initialized image pinned. Native ARM64 checks cover suspension/resume, checked output writes, abandoned requests, void constructor returns, nonzero start failure and successful stop/finalization. This connects lifecycle management to suspension; caller argument sharing, catalog loading and dynamic dependency pins are now connected. The whole-homebrew runner has not switched to this path.

Guest module execution now borrows the complete started dependency closure, maps its code/data alongside the caller and switches load bias on cross-image calls and returns. Image-specific translation registrations distinguish identical offsets in different modules, and every block still checks its source bytes. Older executors explicitly reject dependency images instead of ignoring them. Native ARM64 tests run a three-image chain through relocated indirect calls, write caller data from the leaf and restore both return frames. A faulted consumer now prevents provider stop as well as unload; successful chains stop/unload in dependency order. Automatic root selection, compilation of newly discovered indirect targets and kernel-driven loading remain unimplemented.

`module_compiler.rs` now connects bounded code discovery to native module execution on Apple Silicon macOS. Given explicit roots and the matching trusted Rust runtime archive, it emits ARM64 assembly, invokes Xcode tools to build a local library and registers every discovered instruction boundary under the image load bias. Each registration retains the generated library and checks the entire source block before execution. Failed preparation publishes no blocks; duplicate images and instruction-budget failures reject explicitly. Removing an image’s translations releases the library and its temporary files once execution is quiescent. The API is unsafe because the host must supply the exact compatible runtime archive; no guest-supplied host library is accepted implicitly. Unsupported discoveries remain reported boundaries and cannot execute as native guest bytes. Native tests compile a relocated-import fixture and a three-image call chain without manually registering their blocks, exercise interior instruction entry and verify library cleanup. This is bounded ahead-of-time compilation, not a complete game JIT or PS5 loader.

`module_files.rs` provides an explicit guest-path catalog backed by already-open regular host files. Guest paths are exact catalog keys and never become host paths; malformed paths, duplicate registrations, more than 128 sources and reads beyond the remaining budget fail. Replacing a host pathname does not redirect its retained descriptor. Host assets must not be edited concurrently. `Modules::load_file` reads and validates a catalog image; `load_start_file` runs its real executor and returns success only after initialization completes. Failures after loading retain the handle/image and report that handle to the caller. This is file-backed loading with configured entry offsets, not automatic firmware discovery or a connected kernel syscall. The native Rust test reads standard/SCE fixtures from disk and executes their initializers and start/stop routines as translated ARM64.

`lifecycle.rs` discovers standard/SCE `DT_INIT`, `DT_FINI` and relocated init/fini arrays. It validates mapped array bounds, executable targets, count limits, complete pointer/size pairs and conflicting aliases. Initialization runs direct init then array order; finalization runs reverse array order then direct fini. Null/sentinel array entries are skipped. Constructors use a separate void-call executor contract; their return registers are not interpreted as module status. Shared-module preinit arrays and entries outside the owning image remain unsupported. Constructor/finalizer failures pin the module in its faulted state.

A native Rust test loads synthetic standard/SCE ELF modules, automatically discovers their constructors/finalizers and executes those plus explicit start/stop routines as generated ARM64. It verifies call order, nonzero void-return registers, real guest RET/status/fuel, unload and stale handles. This fixture has register-only routines; it does not demonstrate arbitrary library initialization or gameplay.

Addresses accept decimal or `0x` hexadecimal. Prefix translation stops at its first CALL/RET. Unsupported instructions remain reported boundaries, not no-ops. `verify-decoding` checks the input SHA-256 and independently decodes every legacy block to its exact end/count; the current graph must retain every legacy instruction PC and account for every legacy unsupported boundary, either as newly supported code or an explicit failure. It emits the current Rust graph, allowing new instruction coverage to extend the baseline. It does not prove semantic equivalence by itself.

## Initial MacPS5 repository snapshot

The published source snapshot passes 203 unit tests, three integration tests and strict Clippy. Full-width worker-return implementation is present, with its native verifier prepared but not yet executed against a matching release. It does not implement pthread_create or scheduling.

An experimental integer-only multiplication engine is present but is not used by the translator. Its independent finite LLVM corpus comparison currently fails: 159,752 accepted cases, 9,780 result/status mismatches, and 44,344 unsupported cases. See [the reproducible comparison](../tools/fp-oracle/README.md). These differences must be resolved or justified against AMD/x86 semantics before enabling execution. Unit tests alone do not validate this engine.
